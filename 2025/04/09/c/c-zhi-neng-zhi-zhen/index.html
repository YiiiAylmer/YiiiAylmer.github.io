C++智能指针

参考资料:

  • 30分钟讲明白现代C++最重要的特性之一：智能指针

1 裸指针与内存泄露

  • 动态分配内存：new请求的内存必须用delete手动删除
    int *p = new int[100];
delete[] p; //手动删除了new出来的数组,p仍然存在
  • 栈内存：当你调用一个函数，局部变量就分配在栈内存，函数调用结束局部变量就自动释放，这个过程由编译器自动控制
  • 堆内存：用于动态分配内存，需要程序员手动请求这块内存，使用完需要程序员手动释放，不然这块内存就会一直存在
    int foo(int x){
    int y=x*2;
    int *p=new int[5];
    p[0]=y;
    // delete[] p;  //若无delete，那么就会出现内存泄漏
    //结束后，x,y,p内存释放，但是new出来的int[5]内存不会释放
}
  • nullptr比NULL更安全：因为NULL本质上是0，编译器可理解为int导致混乱

2 共享指针shared_ptr

  • 共享指针指向同一个物体，会记录其数量，数量降为0时，程序将自动释放该物体
  • #inclde<memory>
  • 初始化
    shared_ptr<int> p;
p=make_shared<int>(100);

shared_ptr<int> p {make_shared<int>(100)}; // 尽量使用make_shared
shared_ptr<int> p {new int(100)};
  • 自动管理内存-引用计数：当前指针所指对象的共享指针数量
    shared_ptr<Ball> p=make_shared<Ball>();
cout<<p.use_count()<<endl;
shared_ptr<Ball> p2=p;
cout<<p.use_count()<<" "<<p2.use_count()<<endl;
shared_ptr<Ball> p3=p;
cout<<p.use_count()<<" "<<p2.use_count()<<" "<<p3.use_count()<<endl;
p.reset();p2.reset();p3.reset();
  • 习惯：使用共享指针时避免裸指针
  • 补充用法

    • 获取裸指针： Ball* rp=p.get(); //rp为裸指针，指向共享指针p所指对象

    • reset():带参数时，将修改shared_ptr已指向的对象改为参数所指对象

    • p.reset(new Ball);

    • 自定义删除函数:shared_ptr<FILE> sfp {FILE* fp, editing_function}

    • 别名

      struct Bar{int i=123;};
struct Foo{Bar bar;};
int main(){
  shared_ptr<Foo> f=make_shared<Foo>();
  cout<<f.use_count()<<endl; //1
  shared_ptr<Bar> b(f,&(f->bar)); //b共享指针指向了 f指针所指对象实例的bar属性，那么此对象有两个共享指针计数、其中一个指向Bar类型的bar
  cout<<f.use_count()<<endl; //2
  cout<<b->i<<endl;
}
      • 危险行为及缺陷
        • 使用共享指针就，避免使用手动delete
        • 由于存在引用计数，存在额外的内存、性能开销

3 独享指针unique_ptr

  • 共享指针相比于裸指针，性能下降
  • unique_ptr独享指针：一种零开销的智能指针，智能管理内存且无额外开销，推荐任何情况使用
  • 初始化/避免异常导致的内存泄漏
    unique_ptr<int> UP=make_unique<int>(100);

Object* p=new Object;
p->foo();
delete p;
//若在第二行foo()函数出现异常终止，那么将没有执行delete，产生内存泄漏

unique_ptr<Object> up {make_unique<Object>()};
up->foo();
//若抛出异常，也能正确释放内存
  • 其他用法
    • 裸指针：Ball *p=up->get();
    • 释放/重指向：up.reset() up指向nullptr / up.reset(new Ball{});
    • 指针解绑：release()，返回资源的裸指针
  • 由于unique_ptr独占一块内存的控制权，故不支持普通拷贝
    unique_ptr<int> up1=make_unique<int>(100);

unique_ptr<int> up2(up1); //Error
up2=up1; //Error
unique_ptr<int> up2(up1.release()); //up2获得了控制权，完成控制权的转移
unique_ptr<int> up2=move(up1); //使用std::move 完成转移
  • 自定义分配函数和释放函数
    • 默认使用new分配和delete释放
    • unique_ptr绑定释放函数在编译期，避免了运行时绑定的时间损耗。
    • shared_ptr自定义释放函数在运行时绑定
  • unique_ptr函数传递时的注意事项
    • 由于不支持普通拷贝
      void main(){
  auto up=make_unique<int>(123);
  func(up);  //不可拷贝，编译错误  定义 void func(unique_ptr<int> up)
  func1(*up);  //up指针指向的对象 定义 void func1(int& value)
  func2(up.get());  //裸指针指向资源对象 定义 void func2(int* p)
}
    • 上面代码不能改变unique_ptr本身:函数定义时使用独享函数引用
      void func3(unique_ptr<int>& up){
  cout<<*up<<endl;
  up.reset();
}
void main(){
  auto up=make_unique<int>(123);
  func3(up);
  if(up==nullptr) cout<<"up is reset.";
}
    • std::move用法
       void func4(unique_ptr<int> up){
  cout<<*up<<endl;
}
void main(){
  auto up=make_unique<int>(123);
  func4(move(up));
  if(up==nullptr) cout<<"up is reset.";
}
  • 函数返回unique_ptr：需要理解函数返回细节

4 弱指针weak_ptr

  • weak_ptr是观察者，没有资源的管理权限；可以检查资源是否存在
  • 适用于不需要控制资源但想检查资源是否存在
  • 为什么使用弱指针
    • shared_ptr环形依赖
      struct Teacher{
  string name;
  shared_ptr<School> school;
};
struct School{
  string name;
  shared_ptr<Teacher> principal;
};
int main(){
  auto princp=make_shared<Teacher>();
  auto university=make_shared<School>();

  princp->school=university;
  university->principal=princp;
  return 0;
  //程序结束之后，Teacher、School对象都没有被释放
  //因为Teacher对象结束生命周期时，发现存在university对象，不能执行析构
}
  • weak_ptr用法
    weak_ptr<int> wp;
shared_ptr<int> sp=make_shared<int>(100);

wp=sp;  //初始化一个弱指针 需要一个 shared_ptr 或 weak_ptr
//使用weak_ptr 访问资源时，需要临时转换成共享指针
//要访问对象，使用lock() 返回一个shared_ptr ,若指向的资源已释放，返回nullptr
auto resource=wp.lock();
if(resource){
  cout<<*resource<<endl;
}
else{
  cout<<"wp is expired";  //wp已经过期了
}
  • 如何解决环形依赖
    struct Teacher{
  string name;
  //shared_ptr<School> school;
  weak_ptr<School> school;
};
struct School{
  string name;
  shared_ptr<Teacher> principal;
};
int main(){
  auto princp=make_shared<Teacher>();
  auto university=make_shared<School>();

  princp->school=university;
  university->principal=princp;
  return 0;
  //程序结束之后，Teacher、School对象都没有被释放
  //因为Teacher对象结束生命周期时，发现存在university对象，不能执行析构
}
